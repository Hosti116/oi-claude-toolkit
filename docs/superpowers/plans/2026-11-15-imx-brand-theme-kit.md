# Kit temi di brand Web Portal — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Skill, agente, template e script in `oi-toolkit` che da un `brand.json` producono temi chiaro/scuro del Web Portal OIM 10.0 pronti per il Software Loader, con verifiche automatiche in Chrome; collaudo: rigenerare Pilota identico al deploy attuale.

**Architecture:** Il plugin runtime (`BrandThemeService` nel `ccc` del workspace) è identico per ogni cliente e legge la configurazione da variabili CSS dichiarate dai temi. Il generatore PowerShell scrive solo SCSS, logo e config del cliente; build e pacchetto applicano come controlli bloccanti le lezioni di CHG-<n>.

**Tech Stack:** PowerShell 7.6 (script, test con `Assert-True` come `tests/Test-OiToolkit.ps1`), Sass/postcss/esbuild dal `node_modules` di `imxweb`, Angular 20 + Karma/Jasmine (plugin `ccc`), Chrome via Claude in Chrome.

**Spec:** `docs/superpowers/specs/2026-11-15-imx-brand-theme-kit-design.md`

Repository: **T** = `C:\oi-claude-toolkit` (kit); **W** = `<workspace>` (lab; submodule `oim/webportal/imx`, branch `custom/v100`).
Skill folder abbreviata **K** = `T/plugins/oi-toolkit/skills/oneidentity-imx-brand-theme`.

## Global Constraints

- Nessun nome di cliente, hostname o path assoluto nel toolkit: `tests/Test-OiToolkit.ps1` e `tests/Invoke-OiLeakScan.ps1` verdi. Esempi con id `acme`.
- Classi dei temi: `<id>-light-theme`, `<id>-dark-theme`; `id` kebab-case `^[a-z][a-z0-9-]{1,30}$`.
- Contratto CSS (unico tra SCSS e plugin):
  - su `:root`, identiche nei due CSS: `--ccc-brand-light-class`, `--ccc-brand-dark-class`, `--ccc-brand-device-theme` (`brand`|`standard`);
  - in `:where(body.<classe>)` di **ogni** tema: `--ccc-brand-map-<shade>` (mappa base);
  - solo nel tema scuro: `--ccc-brand-dark-fg-<shade>`, `--ccc-brand-dark-surface-<shade>`, `--ccc-brand-dark-fill`, `--ccc-brand-on-dark-fill`;
  - `<shade>` ∈ `blue10 blue15 blue20 blue40 blue60 blue80 blue85 blue90 orange10 orange15 orange20 orange40 orange60 orange80 orange85 orange90`; valori hex `#rrggbb` minuscoli.
- Soglie: accento scuro ≥ 4.0:1 su `#444647` e ≥ 4.5:1 su `#1e1e1e`; riempimento scuro con `#ffffff` ≥ 7:1; controllo scanner: testo < 3:1 = anomalia.
- Build: Material scoped `:where(body.<classe>)`; 0 `@font-face`; 0 dichiarazioni non scoped diverse tra i due CSS; portale con `--skip-nx-cache`.
- Deploy: `Urls` = `../qer-app-portal/<id>/<classe>.css`; staging che rispecchia `bin\imxweb`; ruolo `Server\Web\Business Api Server`; copia in `bin` e riciclo `<API Server app pool>` solo con OK, mai con `Tipo` diverso da LAB/TEST/DEMO.
- File generati marcati in testa `GENERATED by oi-toolkit <versione> — do not edit` (commento del linguaggio).
- Script eseguiti con `pwsh -NoProfile -File`; output finale degli script: una riga JSON.
- Commit con riga finale `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; nessun push.

## Review Focus

1. Brand con primario chiaro (es. giallo `#ffd200`): tema chiaro con testata del primario e logo `onBrand` → il testo/icona sulla testata deve restare leggibile; il generatore sceglie il colore di testo della testata per contrasto (test in Task 1, `Get-OnColor`).
2. `brand.json` con override `dark.accent` sotto soglia → avviso esplicito, non blocco (test in Task 2).
3. Workspace senza `ccc` o con `InitService` già modificato da altre personalizzazioni → il generatore non sovrascrive, inserisce la sola registrazione o si ferma con istruzioni (test in Task 6).
4. Rigenerazione dopo modifica manuale di un file GENERATED → stop con elenco dei file, nessuna scrittura (test in Task 3).
5. Portale caricato dalla cache del browser dopo l'import → lo scanner segnala `main` diverso da quello del pacchetto invece di riportare falsi esiti (test in Task 8).
